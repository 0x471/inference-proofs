    Fidelity

    Proved UD-Q4_K_XL (new tab) (GGUF), 4.84 bits per weight, computed from its files (new tab); integer weights, fixed-point activations, as the publisher states: “Model is Llama 4 Maverick's text transformer in integer arithmetic: integer weights, fixed-point activations with fitted power-of-two scales, and lookup tables for the non-linear functions” (new tab)

    Fidelity asks whether the model FlashProve proves answers like the original, the 16-bit model its publisher released. Proving usually runs a copy whose numbers are stored in fewer bits (quantization), and FlashProve proves UD-Q4_K_XL (GGUF), 4.84 bits per weight, computed with integer weights and fixed-point activations. Each row below is fed the same 360 prompts, each followed by the original's reply. Its Fidelity figure is the share of the reply's positions where its top token is the original's next token: 100 % means the original's choice at every position. The 8-bit copy (Q8_0) and the 4-bit copy (Q4_K_M) are the original with its weights rounded to 8 bits, and mostly to 4 bits, by llama.cpp; we run them without a proof, as yardsticks. The level file fixes, before any run, which copies are honest (the original run again and its 8-bit and 4-bit copies) and which are damaged on purpose; the bar is the highest-scoring damaged copy that every honest one scores above.

    Why top-token agreement: a greedy reply is the top token at each position, so this counts how often the proved model makes the original's choice, at every one of the 512 positions, not only up to the first difference.

    Matched leading tokens set the Fidelity check and the Fidelity petal: the tokens at the start of each reply that equal the 16-bit original's, counted up to the first difference. The Fidelity check passes when the replies the system proved match more of them than the bar, a damaged copy, by a paired test at p < 0.05. The Fidelity figure sets no state. Neither compares logits: the KL columns do.

    KL to the original weights: not measured (llama.cpp's KL base is the 16-bit file, which the level's llama.cpp pin cannot run on this rung)
