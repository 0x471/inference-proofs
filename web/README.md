# The public site

This folder contains the public site for www.inferenceproofs.ai, styled under the design concept "The instrument" (within the brand "Made of words"), initially served with `noindex` in preview builds. Its structure and display rules follow RFC-0018 §Site (SI-1 to SI-8).

Pages generated by `iproofs site build` and served at clean URLs: `/` (the ladder), `/overview` (all benchmarked systems on one plot; formerly `/scale` until 2026-11-20), one page per board row (`/<system>`, or `/<system>-<model>` when a system runs on more than one model), `/checks` (the six checks, ordering rule, and scope limits), `/mandate` (under Learn and listed on its hub), `/autoresearch` (announced and not open yet: displays "Coming soon" above its title along with the planned track overview from `learn/autoresearch.md`, excluded from search indexing), the Learn pages (`/learn`, `/proof-of-inference`, `/how-a-check-works`, `/deployment`, `/method`, `/statement`, `/forward-pass`, and `/glossary`), and the 404 page. Retired routes redirect via `GONE` in `draw/outputs.py`: older site pages (`/criteria`, `/reference`, `/release`, `/targets`), eight Learn pages merged into others (`/why-verify` and `/before-you-rely` to `/proof-of-inference`, `/three-ways` and `/treaty` to `/deployment`, `/inference` and `/proof-systems` to `/forward-pass`, `/architectures` to `/statement`, `/cost` to `/method`), and any level system without a page yet.

## Build and check

From the repository root:

```
uv run iproofs site build                                   # into web/, from the newest releases/v1.*/board.json, or the level file alone
uv run iproofs site build --board PATH --out DIR            # a preview from a given board file
uv run pytest web -q                                        # figures, states and order against the board file
```

The build writes all HTML pages, `404.html`, `search.json`, `vercel.json`, the Open Graph card sources in `og/`, the fonts block in `words.css`, and the contrast table below. Passing `--out DIR` writes a complete standalone copy elsewhere with static assets included. The build never deletes files on its own; if a previously generated page is no longer written, the build stops with an error.

Run `python3 -I serve.py` to preview this directory locally at http://127.0.0.1:4440/ using the rules from `vercel.json`. To render Open Graph card sources into `og/*.png`, run `PLAYWRIGHT_MODULE=<path to playwright/index.mjs> node og.mjs` (set `OG_CHANNEL=chrome` to use a local Chrome install instead of Playwright's bundled browser), then rerun `iproofs site build` so the HTML pages reference the updated image hashes. Whenever the display font file changes, run `<python with fonttools and uharfbuzz> -I wordmark.py` to regenerate the wordmark outlines in `fonts/wordmark.json`; the build fails if those outlines point to a different font file.

## Deploy

Vercel serves this directory (with Root Directory set to `web`) straight from git: `buildCommand` copies the HTML pages, `words.css`, `words.js`, `search.json`, images, and fonts into `public/`. The build generates `vercel.json` with redirects, cache rules, and a Content-Security-Policy that hashes the single inline script by its SHA-256 digest. On every change to a site input, `.github/workflows/site.yml` rebuilds the site and fails if any committed file under `web/` drifts from the generated output.

## Data

`iproofs site build` reads five sources: `levels/L1.yaml`, the newest Level 1 release's `releases/<release>/board.json` (schema `board/1`, or the path passed via `--board`), the claim cards `systems/<system>/claim.yaml`, `_data/facts.json` (schema `site-facts/1`: display names, licences, operator credits under `credit`, and each unrun system's fixed reason under SI-4), and the Learn Markdown sources under `learn/`. When no Level 1 board is present, every rung in the level file renders as not run yet.

`iproofs.site` compiles these inputs into a single deterministic view with no git calls and no clock reads; the renderer (`build.py` and `draw/`) draws exclusively from that view without opening any data files. Every displayed number comes from a `quantity/1` value in the board file, formatted to four significant digits in a readable unit, with its full labels and JSON Pointer source inside its hover title. Scope and sample size (`n`) appear on each system page (under the band's figure, once for the Cost block with exceptions noted under any differing figure, and in the caption of the Fidelity plot) and once per row on Learn pages below the multiple (leaving the parts, verify time, and proof size unannotated), rather than on the ladder or Overview page (AGENTS.md rule 2, RFC-0018 SI-8). The renderer never hard-codes numbers. `_data/criteria.json` (RFC-0016) was deleted on 2026-11-15, and no figures from earlier pre-Level-1 releases are displayed (SI-5).

## Design

Content placement is governed by depth: the surface shows results, and each step down reveals more about how they were produced. [`DEPTH.md`](DEPTH.md) documents the full depth map (every depth level, placement rules, how wording shifts with depth, the test for adding a new line, and known gaps), implementing RFC-0018 SI-8. Read it before adding anything to a page.

The site wordmark is set as a formal expression, INFERENCE ⊢ PROOFS, using uppercase Big Shoulders Display 900 outlines (`fonts/wordmark.json`) with the turnstile symbol between the two words at cap height. The turnstile mark ⊢ is constructed on a 20 × 15 unit grid (1 unit = cap height / 15): a solid 3-unit stem with three 5-unit square cells along its centre line separated by 1-unit gaps, the first cell joined to the stem. In the lockup it sits 4 units after the E and 3 units before the P. Below 32 px, it snaps to whole pixels (13 × 9 px at 16 px, doubled at 32 px). `draw/mark.py` generates all uses of the mark: the header logo, the site icon (`og/icon.svg`, touch icon, and 32 px PNG in ground ink on cobalt), and the page badge in search results.

The visual system is "an instrument, made of words": a site built to be operated rather than skimmed like a brochure. Its palette takes Lucid Computing's colours: a night ground (`#07080c`), white text (`#ffffff`), muted text (`#8a8d97`), rules (`#5c5f6b`) and hairlines (`#24262e`), a lift ground (`#111218`) for active rows, and Lucid's flat cobalt (`#1b3bff`) reserved strictly for the benchmark's own chrome, always under white type (top bands, a model's size tab, active tabs and sections, the edge of hovered rows, blocks in hand, and anchor arrivals; never data values or states). Its light, periwinkle (`#93a5ff`), stands in where a thin line or a word must read on the night: the turnstile mark, focus rings, a name in hand. State inks fill petals and state chips (ground ink on green, amber, or red, with undecided and hollow states drawn as outlines), with no gradients, glows, or drop shadows. Names, headings, and positions use Big Shoulders Display (weights 800 and 900), while all labels and numbers use Martian Mono (weights 400 to 600, width 87.5) on a tight typographic scale. Page titles (Checks, Mandate, 404, and Learn pages) match the home title size (`--title`); only a system's name on its own band is larger. Both fonts are self-hosted in `fonts/` alongside their licences (`OFL-BigShoulders.txt`, `OFL-MartianMono.txt`); Martian Mono falls back to system monospace after 100 ms while loading, whereas Big Shoulders waits for its font file. Cell grids share meeting hairlines with no central stem.

What stays in view: the top bar (lockup, the tabs Ladder, Overview, Learn, Checks and Autoresearch, search, GitHub; a system page marks Ladder, and a Learn page, the glossary and the mandate mark Learn; Learn only when the tree holds the Learn words; on a phone in two lines, the tabs 44 px tall, stepping away on the way down and back on the way up (a jump to an anchor sets it first, so the anchor lands right under what stays), and the same step-away on a phone held sideways, which also gets the 16 px field and a list that ends above the keyboard); on the ladder its heads and, under them, the divider of the model whose rows are passing; on the other pages a strip of the page's sections, the one in view marked (the one whose heading, or the anchor the address names inside it, sits right under the strip, else the earliest of those whose heading has passed a third of the window under it and is still under the strip, else the last that has passed, and at the page's top the first; at the page's end the last, unless the section a link went to is in view; it reads them again once the strip has moved with the top bar), the strip starting on a label's edge, the page's title in it once the band is gone, ruled on its right once stuck (not on a Learn page, whose chapter row and band name it, so every label stays whole; on a phone a label longer than the strip takes two lines). On a touch screen a target is 44 px (an evidence link 26 to 32 px above a phone's width, so a check's list stays a list, and 40 px on a phone; a check's "not run" 25 to 32 px, between neighbours; a row's standing and the ladder's figure heads 40 px; the checks page key's arms answer over half of each gap beside them; on a phone the glossary page's letters share the strip's width, about 20 px each and 44 px tall, rather than scroll); the search field is 44 px tall with 16 px words, and on a tablet, in use, the field widens over the tabs to its list's width (420 px), the tabs stepping aside and the list hanging under it. Each section keeps a heading at a modest display size; the first one, right under the strip, is for screen readers only.

The glyph renders a row's state as a five-armed turnstile (RFC-0018 §The glyph): a cobalt stem with five horizontal arms from top to bottom (Integrity, Confidentiality, Fidelity, Formally verified, and Trust assumptions). Each arm displays the petal's name in ground ink over its state ink (green, amber, or red, with a strikethrough name for Not met and Failed; Not decided is drawn as an outline with muted text, and inks are never written out as colour words). Two steps modify the arm geometry rather than the ink (§The glyph, Q7): Partly met is cut (stopping 1 unit short of a 5-unit end cell, keeping the gap at least 2 px and the end cell at least 3 px), and a red petal caused by silence is open (a hollow red outline with unstruck red text, switching to paper text on lifted rows so contrast stays above 4.5:1). Each arm carries its form as a CSS class (`cut`, `open`) and its `data-step` and `data-cause` attributes, while the full state and step appear in screen-reader text and in the grade word of the system page's Criteria rows. The glyph follows the mark's grid units (3-unit stem, 5-unit arms, 1-unit gaps; 3 px per unit where it carries its petals' names, 159 × 87 px), keeps identical arm lengths across all states, and omits labels below 3 px per unit (the ladder at 2 px per unit, 50 × 62 px, since 2026-11-23; search results and the 404 page). It never shows state words or numbers inside the graphic. A system page draws no glyph (amended 2026-11-22, RFC-0018 Q53): its Criteria section grades the five petals in words and tracks (System page, below). On the Checks page, a cobalt key draws the five arms as links to their four step rules. Every arm embeds its ink in SVG attributes so glyphs remain readable without CSS. On the Checks page, pointing at a petal of the key highlights its rules (and the rules its petal); above 900 px (while the key sits beside the rules), the active petal in the key stays solid cobalt while the others switch to cobalt outlines with paper labels.

Interactive responses use motion only when `html.anim` is active and respect reduced-motion preferences, keeping every transition under 250 ms and never animating numeric values so no unmeasured intermediate number ever appears. Rows, search results, and 404 cells act as full press targets that lift with a cobalt edge on hover and widen on focus or press. Tabs, strip links, and the GitHub link fill upward with cobalt in 120 ms and clear immediately on leave. Footer links and Mandate rule lines switch instantly to cobalt under ground ink on hover, press, or focus (with a paper ring on focus), and links inside bands or the Learn masthead mirror pointer feedback on keyboard focus and press. The search dropdown unrolls along a crisp edge with matched terms highlighted. Landing on an anchor on the Checks page (a petal, check, figure, cause, or rule) sweeps a cobalt highlight block across its heading from the left (`clip-path`, 240 ms). Inside the ladder, `j` and `k` (or arrow keys from a focused row, falling back to page scroll at the first and last rows) step through rows, and returning from a system page via an in-site link keeps that row marked (reloads and the browser Back button clear the mark). Hovering, focusing, or tapping a figure reveals its full hover labels (scope, grade, evidence, n, and record) beneath it, and doing the same on a glyph petal displays its name, step, and cause (for red or hollow petals). A second tap or a tap elsewhere dismisses the tooltip, clicking keeps it open, and in a ladder row each figure links directly to its corresponding section on the system page (multiple, cost, and verify time to Cost; Fidelity to Fidelity) while tapping anywhere else in the row follows the row link. Moving the pointer across the dark gap between two arms of a glyph keeps the previous arm active so tooltips never flicker. Tooltips fade in place without sliding, stay within page gutters, position below the figure (or below the whole glyph for petals), flip above when near the viewport bottom or to the side if vertical placement would obscure another figure, and avoid covering model names, the ladder's stuck heads or a model's stuck divider whenever clear space exists. Moving the pointer onto a tooltip (or a glossary term's preview) keeps it open and hides it 250 ms after leaving (yielding immediately if the pointer moves onto another figure beneath it). If the viewport is too short, tooltips scroll internally (with arrow keys when triggered by focus), and keyboard focus scrolls the figure cleanly beneath sticky bars first. Clicking a figure's text in a row waits one double-click interval so double-clicking still selects text. Open tooltips act as accessible descriptions for screen readers, and focus-triggered tooltips and glossary previews track their anchor during scroll. Pressing Ctrl+K, Cmd+K, or `/` (outside inputs) opens search without scrolling the page. Cross-document view transitions (`@view-transition`) swap pages instantly without a root crossfade while preserving the top bar, sliding the active tab indicator, and morphing a row's name into its system page title and back (the system page draws no glyph, so the row glyph does not morph; transitions to or from other pages swap immediately). In print styles, bands print on paper with cobalt rules, interactive controls hide, disclosures expand automatically when JavaScript is active (restoring their state afterward), and petals plus labelled fills (size tabs, position 1, and the system's own replies row) preserve their colours. Under forced colours, the wordmark adopts the system text colour, petals and swatches gain crisp borders (hollow petals matching the text colour), and focus styles switch to outlines wherever fills were used.

`words.js` implements all client-side enhancements: search ranking (exact name matches first, then prefix matches, then words within a name, then body text; each group appears once at its highest-ranked match), row click targets and `j`/`k` navigation, a single animation-frame scroll handler (updating the sticky section strip, phone top bar, Checks page key highlight above 900 px, dismissing hover tooltips on scroll, and repositioning focus tooltips), the Checks page key's petal highlighting, a criterion opened when a link names it, figure label tooltips, and the Learn page explorers. Everything CSS can handle natively (hover, press, and anchor arrival) stays in CSS. A single tiny inline script (`HEAD_SCRIPT` in `draw/chrome.py`) runs before first paint to add `html.js`, add `html.anim` unless reduced motion is requested, tag the returning row name during view transitions so it morphs back cleanly, and set morph durations to 200 ms with a fast ease-out. `vercel.json` allowlists this script by its SHA-256 hash, and the stylesheet loads ahead of it so `@view-transition` is registered before reveal. Without JavaScript, the entire site remains readable: search is omitted, disclosures work natively, and the Checks page key still links to every petal.

## The Learn pages

`learn/index.yaml` defines the hub copy, two reading tracks (one for policy readers, one for prover teams and engineers) in reading order, and the glossary. Each page lives at `learn/<slug>.md` and is written in a strict Markdown subset implemented in `draw/learn.py`: headings, paragraphs, lists, tables, code, links (site paths, `repo:<path>` for repository files, or URLs), `[[term]]` glossary references, superscript powers such as `2^100`, and fenced `:::name ... :::` blocks (`note`, `stage`, `quote`, `reading`, plus the rendered blocks `figure`, `explore`, and `measured`). Any unsupported construct, stray formatting punctuation (`*`, bracket, or backtick), unknown glossary term, duplicate ID, or dash used as punctuation stops the build. Learn slugs also cannot collide with existing site pages, redirects in `GONE`, or system routes. A `stage` block labels each deployment stage as `measured` (rendered as "Run on this site"), `demonstrated`, `proposed`, or `outside`.

Learn pages obey the same editorial and data rules as the rest of the site. Board figures appear exclusively through `measured` blocks rendered by `fig_html` with full labels, never hard-coded in prose, so every page still builds cleanly without a board file. Prose describes board numbers as "run" or "recorded" rather than "measured" (matching the evidence tiers). Publisher statements are quoted verbatim with line-anchored links at pinned commits. Wording obeys AGENTS.md rule 10 and RFC-0018 SI-5 and SI-6, enforced where possible by `test_learn.py`. Level 1 constants (request shape, margin, and tolerances) are written out in prose and should be reviewed whenever a new level is introduced.

Interactive explorers (`draw/figures.py`) let readers step through worked examples directly on the page. Two explorers exist: the random check of a matrix product, and the sumcheck of an inner product (starting with its lying run). The build renders every case, worked example, and explanation in static HTML so the page works completely without JavaScript; `words.js` progressively enhances them to display one step at a time with interactive controls. Because the arithmetic lives in both `figures.py` and `words.js`, `test_learn.py` verifies `figures.py` against hand-computed cases, and `words.js` cross-checks its own outputs against the server-rendered DOM on startup.

Visually, each Learn page band shows its breadcrumb (Learn and its track, with Glossary at the right end), title, summary, and along its bottom edge the track's pages as cells, sliding a ground-ink highlight across cells via view transitions as you move through the track. The hub band displays both tracks side by side over their page lists, followed by the glossary count and full term index. Below each page band sits the sticky section strip with previous/next position indicators; scrolling strips fade at edges with overflowing labels (where scroll-driven animations are supported), and long labels wrap onto two lines on phones. Section headings hang in a left margin column beside their opening lines, keeping prose near a 72-character measure while figures and tables extend into the right margin. On phones, tables stack cleanly and the session diagram switches to a narrow layout so nothing scrolls horizontally. Previous and Next links at the bottom step cleanly across track boundaries (connecting track ends to the hub, the next track, and the glossary) so clicking Next then Previous always returns you to where you started. Hovering or focusing any glossary link previews its term and opening sentence from build-written `data-g` and `data-d` attributes. The glossary groups terms alphabetically under sticky letter sections, and anchor arrivals highlight target headings with a sliding cobalt block.

The glossary translates the benchmark's own vocabulary from `docs/spec/10-glossary.md` into plain language and defines general cryptographic terms (soundness, zero knowledge, security level) that the specification relies on without defining.

## Files

- `build.py`: renderer entry point (`setup`, `check_stale`, `render`); reloads `draw/` cleanly on each build. `serve.py`: local preview server.
- `draw/`: `state.py` (what `setup` reads), `words.py` (fixed words for stored ids, numbers in reading units, the checks' definitions), `inks.py` (contrast checks), `hexagon.py` (the glyph), `mark.py` (the turnstile, the lockup), `chrome.py` (addresses, fonts, the inline script, the top bar and its tabs, the search field, the section strip, the footer, the page frame, share tags), `ladder.py` (the ladder), `pages.py` (system pages, checks, mandate, 404), `petal.py` (a system page's Criteria section), `overview.py` (the Overview page), `plots.py` (the system page's bars, fidelity tracks and dot plots), `figures.py` (what the Learn pages draw: figures, explorers, blocks of board figures), `learn.py` (the Learn pages, the Autoresearch page and the Markdown subset they are written in), `outputs.py` (search.json, vercel.json, the card sources and icon in og/, the fonts block, the contrast table above).
- `learn/`: Learn source content (`index.yaml` and one `.md` file per page, licensed CC BY 4.0 like the rest of the documentation).
- `conftest.py`, `test_site.py`, `test_learn.py`: automated tests verifying site builds against `harness/tests/fixtures/board/v1.0-example.json` (synthetic values) and empty builds, plus Learn Markdown syntax, links, wording rules, and worked examples.
- `words.css`, `words.js`: site styling and client behaviour (containing no benchmark data). `fonts/`: font files, licences, `faces.json`, and wordmark outlines. `wordmark.py`: regenerates wordmark outlines. `_data/`: `facts.json`.
- `og/`: Open Graph card HTML sources, rendered PNGs, and `cards.json`. The home card contains only the stacked lockup and URL. Each system card summarizes its page at depth 0 (shallower than the ladder, see `DEPTH.md`): the lockup, a cobalt band with the system name (sized to fit one line, or two for long names), model and size, and primary figure on the right (set lightly when unranked), followed by the standing, verify time and proof size per reply, the labelled glyph, the release stamp, and the canonical URL, with every figure showing its unit alone under a plain heading. Each image's alt text states the system, model, primary figure, standing, verify time, proof size, and petals with units. `og.mjs` renders every card source to PNG, records source and output SHA-256 hashes in `cards.json`, and fails if text overflows its container or blocks overlap. If a page's card image is missing or out of date relative to its HTML source, the page falls back to the home card and hides the download button. After updating a board, run `uv run iproofs site build`, then `OG_CHANNEL=chrome PLAYWRIGHT_MODULE=<path to playwright/index.mjs> node og.mjs`, and finally `uv run iproofs site build` again. Each system page's share group (at the right end of the section strip on desktop, or in the band facts on phones) provides a direct card download and a Copy link button powered by `words.js`. `og/members.html` (a social card listing project members) is generated once `credit.members` in `_data/facts.json` is populated.

## Search discovery and production assets

Public pages permit search indexing, while the 404 page keeps its `noindex` directive. The build generates `robots.txt` and `sitemap.xml` from the public page list, excluding the 404 page and redirects. Every public page carries canonical, social, and `WebPage` JSON-LD structured metadata whose hash is allowlisted in the deployment CSP; all descriptions and figures come directly from the compiled site view.

Vercel installs the locked `esbuild` dev dependency, and `assets.mjs` minifies CSS, JavaScript, and the search index into `public/`. Source assets stay readable in git, and committed JSON remains in canonical format. After changing CSS, run `npm run styles` to regenerate minified CSS sections in `styles.json` before running `iproofs site build`. The renderer verifies the CSS source hash, inlines only the rules each page needs (Learn rules only on Learn pages, the Overview page's rules only on its page, and no detail rules on the ladder), and adds their hashes to the CSP so first paint requires no external stylesheet request with or without JavaScript. Locally, run `npm ci --include=dev --ignore-scripts` inside `web/` before running `npm run assets`. Asset URLs embed their source content hashes for cache busting, and web fonts use `font-display: swap` so readers see text immediately while fonts load.
